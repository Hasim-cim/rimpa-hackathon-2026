| 15 Oct | Drop open-domain fact-checking as the core | Crowded, ~72% agreement at best, no IM role | Hasim, research |

| 17 Oct | Product form: **web app** (Streamlit console) over an engine (Python package + FastAPI), plus a **printed passport PDF** for the judges. The gateway proxy is a scale slide, not the demo | Judges are records people; they need something to click and hold. A proxy is invisible on stage | Hasim, Claude |
| 17 Oct | Build the prototype now in a **sibling repo** `~/repos/record-check`, not in `prototype/` | Open question 1 is unanswered. If pre-built code is banned, it's a rehearsal and we rebuild Monday; if allowed, we move it in | Hasim |

| 18 Oct | **One source of truth:** the prototype moved into `prototype/record-check/` (history kept via git subtree); the sibling repo is archived. Rule 5 amended | Parallel chats need one repo to read and write | Hasim |
| 18 Oct | Parallel work runs as briefs in `workstreams/`; each chat updates its brief | So the team can split up without losing state | Hasim |
| 18 Oct | *Lead idea and fallback: TBD on the team call* | | Team |

Plan in `workstreams/07-webapp.md`, log in `docs/versions.md` | Hasim |
| 19 Oct | Stack for production: **Next.js (TypeScript) + the existing Python engine via FastAPI as Vercel functions + Postgres (Neon)**. TS types generated from the OpenAPI schema | Keeps the tested engine; Streamlit and SQLite cannot run on Vercel | Hasim |
| 19 Oct | No real-time correction. Record Check acts when an AI output becomes a record, for the IM | It is a chatbot-runtime feature, performs no records act, and puts us in the crowded guardrails market | Hasim, Claude |

| 19 Oct | IM rules framework modelled on OVIC's **Sample IAR Template V2.0** (`reference/`); ponytail rules (`~/ponytail`) check every version for over-engineering | The IAR is a form IMs already use; ponytail keeps a one-person build small | Hasim |
| 19 Oct | **The engine enforces the filing gate, not its callers.** `passport.build` runs the gate itself (strictest default bar when no document type is named), refuses a tier below the rules and a self-review; the API re-derives citations and verdicts instead of trusting the caller's | "Enforced in the engine, not only in the UI" has to hold for any system that plugs in; a judge can ask how an agent that took actions is kept from being filed as transitory | Hasim, Claude |
| 19 Oct | **One Vercel project (`record-check`, team The Record Breakers) at the repo root, using Vercel Services.** The engine is service `api` (root `prototype/record-check`, entrypoint `api/vercel_app.py`), public at `/api/*`. V2 adds a `web` service and a final `/(.*)` rewrite; `/api` URLs don't change | Frontend and API deploy and roll back together on one domain, previews stay in sync, and V2 is an addition, not a move. Services is beta (Vercel docs, checked 19 Oct) | Hasim, Claude |
| 19 Oct | **ROT in the engine, from session 1 feedback:** drafts never count as evidence; source health labels redundant, obsolete, trivial and draft records; **recall by source record** (a superseded source queues every output that relied on it) | The room named ROT, drafts and outdated versions, and asked to prevent rather than treat; recall already existed for models, so extending it to records is small | Hasim, Claude |
| 19 Oct | **Drop "recall honours faulty-from"**; recall stays over-inclusive (EC-REC-05) | The information manager triages; narrowing by date risks missing records made before the fault was noticed | Hasim |
| 19 Oct | **Stage demo runs on its own DB** (`data/stage.sqlite`, one-line reset); the shared local DB is never reseeded | Several chats share the local DB; the stage needs the new seed records and a clean start | Hasim |
| 19 Oct | **Workflow: planning chat → building chat → deployer chat.** The planner writes specs into the briefs and hands them to the builder; the builder hands finished work to the deployer | Parallel chats, one source of truth | Hasim |
| 19 Oct | **Passport-first UI.** People see the record passport and the checks done on it, each opening to its detail; the other screens move to an information-manager area. One engine view (`passport.view`) feeds both UIs | What the engine has and what people need to see differ; a records person reads a passport, not seven tabs | Hasim |
| 19 Oct | **Passport is a visible card** on the Records page in Streamlit and the web app, not collapsed; the PDF is secondary. Dashboard tile renamed **"Narrow-evidence signals"** (was "Bias risk signals") | People need to see the record; a single-source rule is not a bias detector and records judges would challenge the name | Hasim |
| 19 Oct | **The stage demo gets its own Neon branch** (`stage`), seeded with `scripts/stage.py reset --database-url … --yes`; the shared and production databases are never reset for a rehearsal | Rehearsals need a clean start without wiping what other chats or production hold | Hasim |
| 19 Oct | **Records page follows Hasim's design canvas** in both UIs: headline, visible passport card, then the individual checks (not four grouped lines), each opening to its detail. Colours stay blue / orange / grey | Hasim asked for the console to be rebuilt to the canvas; one design across Streamlit and web | Hasim |
| 19 Oct | **Name: Record Passport. Colours: green = accepted / supported / ready, amber = needs a person, red = blocked / contradicted / not found, grey = not run, each with an icon** (reverses the blue/orange rule) | Hasim, for the demo-ready UI | Hasim |
| 19 Oct | **The narrow-evidence row is called "Bias check"** on the passport (reverses "never call it bias"); the UI never says "unbiased", "bias-free" or "no bias found", and the detail explains it checks the breadth and currency of the evidence | Hasim's choice; the guard keeps it honest for records judges | Hasim |
| 19 Oct | **Two URLs:** presentation at `record-check-stage.vercel.app` (Neon `stage`, trial documents only) and the working app at `record-check.vercel.app` (Neon `main`); the last-slide QR code points at the working app | Judges can explore without changing the data being presented | Hasim |
