# Records-system connectors: research for Record Check (19 Oct 2026)

Markers: a markdown link = page opened and the claim read there. ⚠️ = search snippet only. 💭 = our inference. "Not found" = looked, didn't find.
Note on the coordinator's addition: the builder already has RecordSource (read) and PassportSink (write) with the seed DB as adapter 1. I did not read that code, so the recommendation names the adapter, not the interface details.

## Summary (5 lines)
1. OpenText Content Manager has a REST web service, the "Content Manager Service API" (official PDF confirms it exists; its reference docs are hosted inside the installed service). I could not open the official endpoint/field reference. Record field names (RecordNumber, RecordTitle, RecordDateRegistered...) come from Kapish's Power Connect connector listing, not from OpenText. No public trial or sandbox found.
2. CMIS 1.1 is an OASIS Standard with Web Services, AtomPub and browser (JSON) bindings. Alfresco is the practical free target; OpenText Documentum CMIS support is unconfirmed. Apache Chemistry (OpenCMIS InMemory) is retired (Feb 2022) and not a Docker image.
3. Microsoft Graph v1.0 can read and set a retention label and lock/unlock a record on a driveItem (exact endpoints below). Needs an M365 tenant; the free developer sandbox is now eligibility-gated per forum reports.
4. RecordPoint: documented Swagger/OpenAPI API with a sandbox per a G-Cloud listing (opened). Objective ECM/Gov365: no public API docs found; Objective Connect has a public API but it is workspace/file sharing, not the EDRMS.
5. Recommendation: build a Content Manager adapter on clearly labelled recorded fixtures (not a live system), mapped to RecordSource/PassportSink.

## Q1. OpenText Content Manager ServiceAPI
- Official CM 24.3 Service API guide (opened, PDF text extracted): "The Content Manager Service API is a new Web service designed with a focus on Mobile and Web Consumers. The bulk of the documentation for the service is hosted within the service itself and can be viewed after installation." Installs as a feature of the main CM installation (IIS, Windows or Basic authentication). Links to SDK docs and samples. [CM24.3 ServiceAPI PDF](https://microfocus.com/documentation/content-manager/24.3/CM24.3_ServiceAPI.pdf)
- That PDF does NOT list endpoints, fields or auth flows (it is 10 pages of setup). Consequence: the endpoint paths (e.g. `/Record?q=...`) are not confirmed by an OpenText page I opened. Not found.
- Third-party but opened: Kapish's Power Connect connector on Microsoft Learn shows the operations and parameter keys of a ServiceAPI-backed connector. Find Records: `q` (search query) and `properties` (comma separated list, e.g. `RecordNumber,RecordTitle`); Find Record by ID: `Id`, `properties`, `propertySets`; Create Record (Document): `RecordRecordType`, `RecordTypedTitle`; Attach Electronic File: `File`, `Uri`; other operations include Update Record (Finalise), (Dispose), (Close), (Classification), (Set User Label). Requires "An externally accessible Content Manager ServiceAPI". [Content Manager Power Connect](https://learn.microsoft.com/en-us/connectors/contentmanagerpowerc)
- Record property names as that connector's CMRecord schema gives them (same page): `RecordNumber`, `RecordTitle`, `RecordRecordType`, `RecordDateRegistered`, `RecordDateCreated`, `RecordDateModified`, `RecordDateClosed`, `RecordDateFinalized`, `RecordDateInactive`, `RecordOwnerLocation`, `RecordRetentionSchedule`, `RecordClassification`, `RecordSecurity`, `RecordMimeType`, `RecordNotes`, `RecordExternalReference`, `RecordFilePath`, `Uri`, `Fields` (additional fields object). Note: these are the connector's names; the "Record" prefix pattern matches what you would expect from CM property ids but I did not confirm raw ServiceAPI JSON keys on an OpenText page.
- There is NO standard "status current/superseded" property in that list. 💭 Map it via Record Type, `RecordDateInactive`/closed state, or an additional field; this is a design decision, not a CM given.
- Auth (connector page, opened): connector supports OAuth (Confidential Client Flow) and username/password ("System Managed"). Official OpenText page confirming ServiceAPI auth: not opened. ⚠️ A CM 25.1 Zerofootprint guide snippet says ServiceAPI must be set up for OpenID Connect for that integration; a "CM23.4 OpenIDAuthentication" PDF exists (not opened).
- SDK samples repo (opened): [content-manager-sdk/Community](https://github.com/content-manager-sdk/Community/) has samples (C#, a Java sample "to connect to the ServiceAPI", OpenID Connect sample); licences "Unlicense, BSD-2-Clause". SDK docs site (opened): [Content Manager SDK Documentation](https://content-manager-sdk.github.io/Community/) lists help for 8.3 to 10.1, 23.3, 23.4 ("no updates to the help content for version 23.4"). I did not open the version help pages (the one I guessed returned 404).
- Public sandbox or trial: not found. ⚠️ Search snippets showed OpenText's free trial pages are for Documentum/Content Aviator, not Content Manager.
- 💭 Writing: Create Record + Attach Electronic File + Update Record (Finalise) are the actions a passport write-back would use; the Dispose/Close actions show CM has the records-act lifecycle built in.

## Q2. CMIS
- Standard (opened): CMIS 1.1 defines "Web Services, Restful AtomPub and browser (JSON) bindings"; the browser binding is "a new optional binding". OASIS Standard incorporating Errata 01, 19 Sept 2015. [CMIS v1.1](https://docs.oasis-open.org/cmis/CMIS/v1.1/CMIS-v1.1.html)
- Vendor support (Wikipedia page, opened; secondary, dated): servers listed include Alfresco (3.3+), OpenText (ECM Suite, via a CMIS connector over Enterprise Library Services 10.2.0), OpenText Documentum 7.x (no notes), Microsoft SharePoint Server ("CMIS 1.0 is supported out-of-the-box in SharePoint Server 2013"), Nuxeo 5.5+. [CMIS on Wikipedia](https://en.wikipedia.org/wiki/Content_Management_Interoperability_Services). Current Documentum CMIS conformance: not confirmed (⚠️ only third-party snippets). Content Manager CMIS support: not found. Objective/RecordPoint CMIS: not found.
- 💭 So one CMIS adapter would cover Alfresco and possibly Documentum, but NOT Content Manager, SharePoint/Purview (today) or Objective in the Australian-government estate. Do not claim "one adapter reads several records systems" for the target audience.
- CMIS has no standard records fields for disposal class or "superseded". 💭 It exposes documents and properties; records semantics would be custom properties/aspects.
- Free server, Apache Chemistry InMemory: the project page says "This project has retired." and the Attic page says retired February 2022, move to Attic completed July 2022. The InMemory page says you build the WAR yourself, deploy to a servlet engine, data is lost on restart, endpoints given as AtomPub `http://<host>:<port>/<context>/atom`; no Docker mention. [Apache Chemistry InMemory](https://chemistry.apache.org/java/developing/repositories/dev-repositories-inmemory.html), [Attic](https://attic.apache.org/projects/chemistry.html). Recommend against.
- Alfresco Community in Docker: ⚠️ snippets say the official docs describe a Docker Compose quick start (clone acs-deployment, docker-compose folder; dev/test only). I could not open the current docs page (404). ⚠️ Browser binding path seen in snippets for Alfresco: `/alfresco/api/-default-/public/cmis/versions/1.1/browser` (a 5.1 docs page; its URL 404'd when I tried to open it, so unverified for current release). Resource needs, startup time and current image tags: not found.

## Q3. Microsoft 365 / Purview via Graph (v1.0, all opened)
- Read label and record status: `GET /drives/{drive-id}/items/{item-id}/retentionLabel`; permission Files.Read.All (least), Sites.Read.All (higher), delegated or application; no query parameters supported. Response (example) includes `name`, `retentionSettings` { `behaviorDuringRetentionPeriod`, `isDeleteAllowed`, `isRecordLocked`, `isMetadataUpdateAllowed`, `isContentUpdateAllowed`, `isLabelUpdateAllowed` }, `isLabelAppliedExplicitly`, `labelAppliedDateTime`, `labelAppliedBy`. [getRetentionLabel](https://learn.microsoft.com/en-us/graph/api/driveitem-getretentionlabel?view=graph-rest-1.0)
- `behaviorDuringRetentionPeriod` values: `doNotRetain`, `retain`, `retainAsRecord`, `retainAsRegulatoryRecord`, `unknownFutureValue`; `isRecordLocked` is "Specifies whether the item is locked. Read-write." [retentionLabelSettings](https://learn.microsoft.com/en-us/graph/api/resources/retentionlabelsettings?view=graph-rest-1.0). Resource: [itemRetentionLabel](https://learn.microsoft.com/en-us/graph/api/resources/itemretentionlabel?view=graph-rest-1.0).
- Set label: `PATCH /drives/{drive-id}/items/{item-id}/retentionLabel` with body `{"name": "Retention label for Contracts"}`; permissions Files.Read.All least, Files.ReadWrite.All / Sites.ReadWrite.All higher; "Sites.FullControl.All is the least privileged permission required to change retention labels that classify the content as records."; 201 Created first time, 200 OK after. Labels need not be published in a policy to be applied. [setRetentionLabel](https://learn.microsoft.com/en-us/graph/api/driveitem-setretentionlabel?view=graph-rest-1.0)
- Lock/unlock record: `PATCH /drives/{drive-id}/items/{item-id}/retentionLabel` with `{"retentionSettings": {"isRecordLocked": true}}`; Files.ReadWrite.All least. [lockOrUnlockRecord](https://learn.microsoft.com/en-us/graph/api/driveitem-lockorunlockrecord?view=graph-rest-1.0)
- driveItem also has a `retentionLabel` relationship (Read-write) and a `listItem` relationship for SharePoint metadata; methods include Upload, Download file, Search items, Remove retention label. [driveItem](https://learn.microsoft.com/en-us/graph/api/resources/driveitem?view=graph-rest-1.0)
- Not found: a separate `isRecord` property on driveItem; record status is `behaviorDuringRetentionPeriod` plus `isRecordLocked`. There is no "superseded" concept; 💭 versions via `versions` relationship are the nearest thing.
- 💭 Writing a passport: upload a JSON/PDF file (PUT content) or set a listItem field; I did not open those pages.
- Test tenant: ⚠️ 2026 forum threads say the Microsoft 365 Developer Program sandbox is now eligibility-gated and the free configurable sandbox was reported greyed out in July 2026; whether it includes Purview records features: not found. A 3-hour demo that depends on getting a tenant is risky.

## Q5. Recommendation: ONE adapter
Build `ContentManagerSource`/`ContentManagerSink` (implements RecordSource and PassportSink) that talks Content Manager ServiceAPI shapes, backed by recorded fixtures. Reasons:
- Content Manager is the product in the judges' world and the host venue's own (OpenText), so the story lands: "same contract, swap the base URL and credentials".
- It is the only option with zero external dependency in 3 hours. Alfresco Docker (unverified resources and CMIS path), a Graph tenant (eligibility-gated), and RecordPoint (access terms unknown) each could eat the whole 3 hours before one record is read.
- Honest framing is essential: the fixtures are INVENTED, shaped from the property names above, and the ServiceAPI JSON envelope was NOT verified from an OpenText page. Label the demo "contract test against Content Manager-shaped fixtures; not connected to a live Content Manager".
Realistic 3-hour plan (💭):
1. 45 min: before building, get one real ServiceAPI response shape. Ask the mentor/OpenText staff at the venue (host is OpenText) for a sample `Record` JSON, or find it in the SDK samples repo. If you cannot, mark the envelope "assumed".
2. 60 min: fixtures (5-8 records incl. one superseded policy, one with a disposal/retention schedule) and a read mapper: `RecordNumber`->id, `RecordTitle`->title, `RecordRecordType`->record type, `RecordDateRegistered`/`RecordDateCreated`->dates, `RecordOwnerLocation`->owner, `RecordRetentionSchedule`->disposal class, status from a documented rule (e.g. closed/inactive date or a custom field).
3. 45 min: write mapper emitting the Create Record (type = a "Record Check Passport" record type, title, passport JSON as the attached electronic file via the Attach Electronic File shape), written to a local outbox folder plus request log, not sent anywhere.
4. 30 min: tests (offline, keyless) and a one-slide "what is real vs recorded".
Fallback if the builder wants something live: Alfresco Community via Docker Compose plus a CMIS browser-binding adapter, but only after a 15-minute smoke test of the container and CMIS URL; abandon if it doesn't answer in 15 minutes. That adapter would read documents but would need custom properties for status and disposal class.
Second, no-build stretch for the pitch deck only: the Graph `retentionLabel` calls above, shown as "also possible on Microsoft 365".

## Lines we must NOT say
- "Record Check is integrated with / connects to OpenText Content Manager" (it reads fixtures shaped like it).
- "One CMIS adapter works with every records system" (Content Manager, Objective, RecordPoint, Purview: no CMIS support found).
- "Content Manager has a public sandbox" (not found).
- "We use the official ServiceAPI JSON schema" (field names are from a third-party connector; official reference not opened).
- "Microsoft Purview has an isRecord flag" (it is `behaviorDuringRetentionPeriod` and `isRecordLocked`).
- "Graph can mark a document as a regulatory record with a simple app permission" (record-classifying labels need Sites.FullControl.All to change).
- "Apache Chemistry InMemory is a maintained demo server" (project retired Feb 2022).
- "Objective has an open API" (only Objective Connect's public API found, which is not the EDRMS).
- "Passports are records in the system of record" without saying which fields/record type and who owns the record type; the information manager decides.
- "Captures everything" (NAA rule is risk-tiered), and "true/false/fake" wording per CLAUDE.md.
